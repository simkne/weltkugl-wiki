# ESP32-S3-Zero ESPHome Sample

This is a template configuration for the ESP32-S3-Zero configured as a sensor hub. It implements the I2C bus for environment sensors, the mmWave sensor via UART, and local UI elements.

## Sample YAML

```yaml
esphome:
  name: sensor-hub-zero
  friendly_name: "S3 Zero Sensor Hub"

esp32:
  board: esp32-s3-devkitc-1
  framework:
    type: arduino

# Secrets are handled in secrets.yaml
wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password

api:
  encryption:
    key: !secret api_encryption_key

ota:
  - platform: esphome

# I2C Bus for BME280 and BH1750
i2c:
  sda: GPIO8
  scl: GPIO9
  scan: true

# UART Bus for mmWave Sensor
uart:
  - id: uart_mmwave
    tx_pin: GPIO2
    rx_pin: GPIO1
    baud_rate: 256000

sensor:
  # Temperature, Humidity, Pressure
  - platform: bme280
    temperature:
      name: "Hub Temperature"
    humidity:
      name: "Hub Humidity"
    pressure:
      name: "Hub Pressure"
    address: 0x76

  # Light Sensor
  - platform: bh1750
    name: "Hub Illuminance"
    address: 0x23

  # Placeholder for mmWave custom component or text sensor
  - platform: template
    name: "Presence Detected"
    lambda: |-
      return id(presence_binary).state;

binary_sensor:
  # Presence Sensor (simplified logic)
  - platform: gpio
    pin: 
      number: GPIO10 # Example pin if sensor has a digital out
      mode: INPUT_PULLUP
      inverted: true
    name: "Human Presence"
    id: presence_binary

  # Preset Buttons
  - platform: gpio
    pin: 
      number: GPIO5
      mode: INPUT_PULLUP
      inverted: true
    name: "Preset Button 1"
  - platform: gpio
    pin: 
      number: GPIO6
      mode: INPUT_PULLUP
      inverted: true
    name: "Preset Button 2"

output:
  - platform: gpio
    pin: GPIO4
    id: status_led_out

light:
  - platform: binary
    name: "Hub Status LED"
    output: status_led_out
```

## Implementation Notes
- **Board Selection**: Since the S3-Zero is a compact variant, `esp32-s3-devkitc-1` is the most compatible generic board target.
- **I2C Addressing**: 
  - BME280 typically uses `0x76` or `0x77`.
  - BH1750 typically uses `0x23`.
- **UART Mapping**: GPIO1 (RX) and GPIO2 (TX) are the sensor-hub UART, so USB logs stay on the native port. The `GPIO10` presence binary in the sample is a placeholder for a digital output. The mmWave boards in use talk over that UART, not over GPIO10.
- **Buttons**: Configured as `INPUT_PULLUP` with `inverted: true` so they read `ON` when pressed (connected to GND).

# Kitchen Infrared Heater Control

A plug-only infrared heating panel has no internal thermostat. openHAB becomes the thermostat: an ESP32 reports the room temperature, a Shelly plug switches the panel, and one small rule decides when heat is allowed.

::note
This is the **simple first version**. It does on/off and min/max targets only. PIR, runtime alerts, auto-off, and a custom widget can be added later.

**Status:** the live kitchen model already has the four Items; the two Main UI rules and the global alert integration still need to be created.
::

## Keep the first version simple

The controller should do exactly four things:

- Let you switch the thermostat **on or off**.
- Let you set a **minimum** and **maximum** target temperature.
- Switch the relay **on below the minimum** and **off above the maximum**.
- Turn the relay **off** if the temperature reading is missing or stale.

That is enough to run the panel safely while the rest of the setup is still being built.

## Map the live devices

The kitchen already has a Location group (`kuchl`) and an Equipment group (`infrarot_heating_kuchl`). The four Items live under that Equipment group.

| Role | Item | Notes |
|------|------|-------|
| Thermostat on/off | `infrarot_heating_kuchl_Enabled` | Existing. Your intent: should the thermostat run? |
| Heater relay | `infra_heat_kuchl_Power` | Existing. Verify it is linked to the Shelly plug relay channel. |
| Minimum target | `kuchl_Temp_TargetMin` | Existing. Heat below this value. |
| Maximum target | `kuchl_Temp_TargetMax` | Existing. Stop heat above this value. |
| Room temperature | `ZENsoria_01_Temperature` | Existing kitchen ESP32 point, label “Kuchl Temp”. |
| Equipment group | `infrarot_heating_kuchl` | Existing group under `kuchl`. |

::warning
`infra_heat_kuchl_Power` is the relay Item. Verify it is linked to the Shelly plug's `relay#output` channel. Do not use `Shelly_Mobile_Plug_01_Power` for this heater — it belongs to a different plug.
::

::warning
Several legacy temperature Items are stale: `ESP32_01_temperature`, `ESP32_S3_Zero_One_Temperature`, and `ESPHome_One_Temperature` were last updated on 23 September 2026. Use `ZENsoria_01_Temperature` (label “Kuchl Temp”) instead.
::

## How the thermostat works

`infrarot_heating_kuchl_Enabled` is the on/off switch. `infra_heat_kuchl_Power` is the actual relay, controlled by the rule.

| Situation | Relay |
|-----------|-------|
| `Enabled = OFF` | OFF |
| Temperature missing or older than 10 minutes | OFF |
| `TargetMin >= TargetMax` | OFF |
| `Enabled = ON` and temperature ≤ `TargetMin` | ON |
| `Enabled = ON` and temperature ≥ `TargetMax` | OFF |
| `Enabled = ON` and temperature is between the targets | Keep the current state |

The middle row is the hysteresis band. It prevents the relay from chattering around a single setpoint.

The rule also runs every minute. That catches a stale temperature sensor even when the temperature value itself stops changing.

## Verify the items

The live kitchen model already has these four Items. Check the names and links before pasting the rule:

| Item | Type | Example value | Notes |
|------|------|---------------|-------|
| `infrarot_heating_kuchl_Enabled` | Switch | — | Your on/off control. |
| `infra_heat_kuchl_Power` | Switch | — | Relay. Verify the Shelly plug relay link. |
| `kuchl_Temp_TargetMin` | Number:Temperature | 19 °C | Lower target. |
| `kuchl_Temp_TargetMax` | Number:Temperature | 21 °C | Upper target. |

Optional but useful: give the target Items a state description of `%.1f °C` so the UI shows one decimal place.

### Alert source items

Create two Switch Items for the global alert controller. Add each one to both `infrarot_heating_kuchl` and `ORWARN`. Do not link them to a Thing — they are state markers that the thermostat rule sets.

| Item | Severity | Message |
|------|----------|---------|
| `infra_heat_kuchl_Alert_Temperature` | `CRITICAL` | Kitchen heater temperature sensor is stale |
| `infra_heat_kuchl_Alert_Config` | `WARN` | Kitchen heater setpoints are invalid |

For each Item, add metadata namespace `alert` with an empty value and configuration keys `severity` and `message`. The [Global Alert Controller](/iot/openhab/global-alert-controller) reads those keys.

## Create the rules

Create two Main UI rules. Paste each YAML into **Settings → Automation → Rules → + → Code**.

::note
The thermostat raises two source alerts in `ORWARN`. Create the [Global Alert Controller](/iot/openhab/global-alert-controller) and the alert source Items first.
::

### Safe startup

Force the thermostat off after an openHAB restart. The panel must not resume heating by itself after a power cut.

```yaml
uid: infrarot_heating_kuchl_startup
label: Kitchen Heater Safe Startup
description: Forces the heater off after an openHAB restart
configuration: {}
triggers:
  - id: "1"
    configuration:
      startlevel: 100
    type: core.SystemStartlevelTrigger
conditions: []
actions:
  - inputs: {}
    id: "2"
    configuration:
      type: application/vnd.openhab.dsl.rule
      script: |
        infrarot_heating_kuchl_Enabled.postUpdate(OFF)
        infra_heat_kuchl_Power.sendCommand(OFF)
    type: script.ScriptAction
```

### Thermostat

```yaml
uid: infrarot_heating_kuchl_thermostat
label: Kitchen Heater Thermostat
description: On/off thermostat with min/max targets
configuration: {}
triggers:
  - id: "1"
    configuration:
      itemName: ZENsoria_01_Temperature
    type: core.ItemStateChangeTrigger
  - id: "2"
    configuration:
      itemName: infrarot_heating_kuchl_Enabled
    type: core.ItemStateChangeTrigger
  - id: "3"
    configuration:
      itemName: kuchl_Temp_TargetMin
    type: core.ItemStateChangeTrigger
  - id: "4"
    configuration:
      itemName: kuchl_Temp_TargetMax
    type: core.ItemStateChangeTrigger
  - id: "5"
    configuration:
      cronExpression: "0 * * * * ?"
    type: timer.GenericCronTrigger
conditions: []
actions:
  - inputs: {}
    id: "6"
    configuration:
      type: application/vnd.openhab.dsl.rule
      script: |
        val enabled = infrarot_heating_kuchl_Enabled.state == ON
        val tempState = ZENsoria_01_Temperature.state
        val minState = kuchl_Temp_TargetMin.state
        val maxState = kuchl_Temp_TargetMax.state

        val tempStale = tempState == NULL || tempState == UNDEF ||
                        ZENsoria_01_Temperature.lastUpdate == null ||
                        ZENsoria_01_Temperature.lastUpdate.isBefore(now.minusMinutes(10))
        val setpointsMissing = minState == NULL || minState == UNDEF ||
                               maxState == NULL || maxState == UNDEF
        val setpointsInvalid = if (setpointsMissing) {
            false
        } else {
            (minState as QuantityType<?>).toUnit("°C").doubleValue >=
                (maxState as QuantityType<?>).toUnit("°C").doubleValue
        }

        infra_heat_kuchl_Alert_Temperature.postUpdate(if (enabled && tempStale) ON else OFF)
        infra_heat_kuchl_Alert_Config.postUpdate(if (enabled && (setpointsMissing || setpointsInvalid)) ON else OFF)

        if (!enabled || tempStale || setpointsMissing || setpointsInvalid) {
            if (infra_heat_kuchl_Power.state != OFF) {
                infra_heat_kuchl_Power.sendCommand(OFF)
            }
        } else {
            val temp = (tempState as QuantityType<?>).toUnit("°C").doubleValue
            val min = (minState as QuantityType<?>).toUnit("°C").doubleValue
            val max = (maxState as QuantityType<?>).toUnit("°C").doubleValue

            if (temp <= min) {
                if (infra_heat_kuchl_Power.state != ON) {
                    infra_heat_kuchl_Power.sendCommand(ON)
                    logInfo("KitchenHeater", "Heating ON: " + temp + " <= " + min)
                }
            } else if (temp >= max) {
                if (infra_heat_kuchl_Power.state != OFF) {
                    infra_heat_kuchl_Power.sendCommand(OFF)
                    logInfo("KitchenHeater", "Heating OFF: " + temp + " >= " + max)
                }
            }
        }
    type: script.ScriptAction
```

::note
The script uses `QuantityType<?>` so it does not depend on any extra imports.
::

## Build the UI

No custom widget is needed for the first version. Use standard Main UI cards on the existing `kuchl` page:

- an `oh-toggle-card` for `infrarot_heating_kuchl_Enabled`
- an `oh-gauge-card` or `oh-label-card` for `ZENsoria_01_Temperature`
- two `oh-stepper-card` controls for `TargetMin` and `TargetMax` (minimum `10`, maximum `30`, step `0.5`, footer “min” / “max”)
- optionally, a small label for the relay state `infra_heat_kuchl_Power`

The `kuchl` page already has two empty stepper cards. Configure those for the two targets and add the on/off toggle and temperature card next to them. The old “Heizung” card can stay until the new controls are verified, then be removed.

## Test it

| Test | Expected result |
|------|-----------------|
| `Enabled = OFF` | Relay turns off; both heater alert source Items clear. |
| `Enabled = ON`, temperature below `TargetMin` | Relay turns on. |
| `Enabled = ON`, temperature above `TargetMax` | Relay turns off. |
| `Enabled = ON`, temperature between targets | Relay keeps its current state. |
| Set `TargetMin` above `TargetMax` | Relay off; `infra_heat_kuchl_Alert_Config = ON`; global controller shows `WARN`. |
| Stop the temperature updates for 10 minutes | Relay off; `infra_heat_kuchl_Alert_Temperature = ON`; global controller shows `CRITICAL`. |
| Temperature updates again | Heater alert clears; the global controller recalculates. |
| Acknowledge the alert | Notification state clears, but the source alert stays `ON` until the condition clears. |
| Restart openHAB | `Enabled` is set to OFF and the relay is commanded off. |

## Safety notes

- openHAB is not a safety device. A Pi crash or network failure leaves the Shelly relay in its last state.
- Consider a hardware thermal cutoff or a plug with over-temperature protection as a backup.
- Verify the Shelly plug rating against the panel wattage, and keep the panel clear of flammable material.
- Keep the ESP32 out of the panel's direct radiant heat. A sensor that reads too high will stop heating too early.

## Add later

Once the simple version is stable, these can be layered on without changing the basic on/off + min/max model:

- a PIR or mmWave presence sensor for occupancy-only heating;
- a runtime alert and optional auto-off after a configurable number of hours;
- a current-watts Item and a “commanded on but no power draw” fault alert;
- enable push notifications in the [Global Alert Controller](/iot/openhab/global-alert-controller);
- a custom `ZEN_kitchen_heater` widget with mode buttons, runtime, and power history;
- persistence for the target setpoints.

Works with ANY device that can publish to MQTT — ESPHome, Tasmota, custom ESP32 code, etc.

## The Universal Pattern

```
Any Device (ESP32, ESP8266, etc.)
       │
       └── MQTT Topic: home/device/[name]/status = "online"/"offline"
                          home/device/[name]/heartbeat = any payload
                          home/device/[name]/rssi = wifi signal
                          home/device/[name]/ip = IP address
       │
       ▼
openHAB MQTT Broker
       │
       ▼
openHAB Thing (MQTT Topic)
       │
       └── Channels: online (Switch), rssi (Number), ip (String)
       │
       ▼
openHAB Items
       │
       └── [DeviceName]_Online, [DeviceName]_RSSI, etc.
       │
       ▼
UI Widgets (status display, alerts)
```

## Step 1: Create MQTT Topics (Device Side)

### For ESPHome (we already have this):
```yaml
mqtt:
  broker: 192.168.1.XXX
  will_message:
    topic: home/device/esp32-s3-zero-one/status
    payload: offline
    retain: true
  birth_message:
    topic: home/device/esp32-s3-zero-one/status
    payload: online
    retain: true
```

### For Custom ESP32 (Arduino/PlatformIO):
```cpp
// Connect to MQTT
mqttClient.connect("esp32-client", mqtt_user, mqtt_password,
                   "home/device/myesp32/status", 0, true, "offline");

// Publish online
mqttClient.publish("home/device/myesp32/status", "online", true);

// Periodic heartbeat
mqttClient.publish("home/device/myesp32/heartbeat", String(millis()).c_str());
```

### For Tasmota:
```
# Already publishes to tele/tasmota_XXXXXX/LWT
# Just map this in openHAB
```

## Step 2: Universal openHAB Configuration

### 2.1 Create the MQTT Broker Thing (once)

In MainUI:
- Settings → Things → Add → MQTT Broker
- Thing ID: `broker`
- Host: `localhost` (since openHAB is on the Pi)
- Port: `1883`
- (Optional) Username/Password if you have MQTT auth

### 2.2 Create Device Things (one per device)

**Generic Thing Template:**

```
Bridge mqtt:broker:broker "MQTT Broker" [ host="localhost", port=1883 ] {

    // ESPHome Device
    Thing topic esp32s3zeroone "ESP32-S3 Zero One" @ "Living Room" {
        Channels:
            Type switch : online "Online"
                [ stateTopic="home/device/esp32-s3-zero-one/status", on="online", off="offline" ]
            Type number : rssi "WiFi Signal"
                [ stateTopic="home/device/esp32-s3-zero-one/rssi" ]
            Type string : ip "IP Address"
                [ stateTopic="home/device/esp32-s3-zero-one/ip" ]
            Type datetime : lastseen "Last Seen"
                [ stateTopic="home/device/esp32-s3-zero-one/heartbeat" ]
    }

    // Custom ESP32 (PlatformIO project)
    Thing topic customesp "Custom ESP32" @ "Kitchen" {
        Channels:
            Type switch : online "Online"
                [ stateTopic="home/device/custom-esp/status", on="online", off="offline" ]
            Type number : rssi "WiFi Signal"
                [ stateTopic="home/device/custom-esp/rssi" ]
    }

    // Tasmota Device
    Thing topic tasmota1 "Tasmota Plug" @ "Office" {
        Channels:
            Type switch : online "Online"
                [ stateTopic="tele/tasmota_A1B2C3/LWT", on="Online", off="Offline" ]
    }
}
```

Save as: `/etc/openhab/things/devices.things`

### 2.3 Create Items

```java
// File: /etc/openhab/items/all_devices.items

Group gAllDevices "All Devices"
Group gOnlineDevices "Online Devices" (gAllDevices)
Group gOfflineDevices "Offline Devices" (gAllDevices)

// ============================================================
// ESPHome Device
// ============================================================
Switch ESP32S3ZeroOne_Online "ESP32-S3 Zero One" <presence> (gAllDevices)
    { channel="mqtt:topic:esp32s3zeroone:online" }
Number ESP32S3ZeroOne_RSSI "WiFi Signal [%d dBm]" <network>
    { channel="mqtt:topic:esp32s3zeroone:rssi" }
String ESP32S3ZeroOne_IP "IP [%s]" <network>
    { channel="mqtt:topic:esp32s3zeroone:ip" }

// ============================================================
// Custom ESP32 (PlatformIO)
// ============================================================
Switch CustomESP_Online "Custom ESP32" <presence> (gAllDevices)
    { channel="mqtt:topic:customesp:online" }
Number CustomESP_RSSI "WiFi Signal [%d dBm]" <network>
    { channel="mqtt:topic:customesp:rssi" }

// ============================================================
// Tasmota Device
// ============================================================
Switch Tasmota1_Online "Tasmota Plug" <presence> (gAllDevices)
    { channel="mqtt:topic:tasmota1:online" }

// ============================================================
// Statistics
// ============================================================
Number DeviceStats_Total "Total Devices [%d]"
Number DeviceStats_Online "Online [%d]"
Number DeviceStats_Offline "Offline [%d]"
```

### 2.4 Simple Rule for Statistics

```java
rule "Update Device Statistics"
when
    Member of gAllDevices changed
    or
    System started
    or
    Time cron "0 * * * * ?"
then
    val total = gAllDevices.members.size
    var online = 0
    var offline = 0

    gAllDevices.members.forEach[ device |
        if (device.state == ON) online = online + 1
        else if (device.state == OFF) offline = offline + 1
    ]

    DeviceStats_Total.postUpdate(total)
    DeviceStats_Online.postUpdate(online)
    DeviceStats_Offline.postUpdate(offline)
end
```

## Step 3: Simple UI Widget

```yaml
uid: simple_device_status
component: f7-card
config:
  title: Device Status
slots:
  default:
    - component: f7-row
      config:
        style:
          padding: 15px
          backgroundColor: "=(Number.parseInt(items.DeviceStats_Offline.state) > 0) ? '#ffebee' : '#e8f5e9'"
          borderRadius: 8px
      slots:
        default:
          - component: Label
            config:
              text: "=(Number.parseInt(items.DeviceStats_Offline.state) > 0) ? items.DeviceStats_Offline.state + ' offline' : 'All online'"
              style:
                fontSize: 18px
                fontWeight: bold
                color: "=(Number.parseInt(items.DeviceStats_Offline.state) > 0) ? 'red' : 'green'"
    - component: f7-list
      slots:
        default:
          - component: oh-repeater
            config:
              sourceType: itemsInGroup
              groupItem: gAllDevices
              for: device
            slots:
              default:
                - component: oh-list-item
                  config:
                    title: =loop.device.label
                    icon: "=(loop.device.state === 'ON') ? 'f7:checkmark_circle' : 'f7:exclamationmark_triangle'"
                    iconColor: "=(loop.device.state === 'ON') ? 'green' : 'red'"
```

## Testing Your First Device

### 1. Verify MQTT Topics Exist

On Pi:
```bash
# Subscribe to all device topics
mosquitto_sub -h localhost -t 'home/device/#' -v

# Or subscribe to specific device
mosquitto_sub -h localhost -t 'home/device/esp32-s3-zero-one/#' -v
```

### 2. Manually Publish Test

```bash
# Simulate device online
mosquitto_pub -h localhost -t 'home/device/test-device/status' -m 'online' -r

# Simulate device offline
mosquitto_pub -h localhost -t 'home/device/test-device/status' -m 'offline' -r
```

Watch the openHAB item change in MainUI.

### 3. Check openHAB Thing Status

In MainUI:
- Settings → Things → Your MQTT Device Thing
- Should show ONLINE
- Click "Channels" to see if they're receiving data

## Common Issues & Fixes

### Issue: Thing stays OFFLINE

**Check:**
```bash
# Is MQTT broker reachable?
mosquitto_pub -h localhost -t test -m hello

# If this fails, MQTT broker is not running or configured
```

### Issue: Item not updating

**Check:**
1. Thing is ONLINE
2. Channel configuration matches topic exactly (case-sensitive!)
3. Item is linked to channel
4. Topic is receiving messages: `mosquitto_sub -h localhost -t 'your/topic' -v`

### Issue: ESP32 not publishing

**Check ESPHome logs:**
```bash
esphome logs esp32-s3-zero-one.yaml
```

Look for MQTT connection errors.

## Adding More Devices

Once one device works, adding more is easy:

1. **Device side:** Ensure it publishes to `home/device/[unique-name]/status`
2. **openHAB:** Add Thing with that topic
3. **openHAB:** Add Item linked to Thing's channel
4. **Done!** The UI updates automatically.

## Non-ESPHome Devices

### Arduino ESP32 (using PubSubClient)

```cpp
#include <PubSubClient.h>

const char* mqtt_server = "192.168.1.XXX";
const char* device_name = "my-sensor-01";

void reconnect() {
    String willTopic = String("home/device/") + device_name + "/status";
    client.connect(device_name, mqtt_user, mqtt_password,
                   willTopic.c_str(), 0, true, "offline");

    String onlineTopic = String("home/device/") + device_name + "/status";
    client.publish(onlineTopic.c_str(), "online", true);
}

void loop() {
    if (!client.connected()) reconnect();

    // Publish heartbeat every 30s
    static unsigned long lastHeartbeat = 0;
    if (millis() - lastHeartbeat > 30000) {
        String topic = String("home/device/") + device_name + "/heartbeat";
        client.publish(topic.c_str(), String(millis()).c_str());
        lastHeartbeat = millis();
    }
}
```

### Tasmota

Already publishes LWT to `tele/tasmota_XXXXXX/LWT`.
Just use that topic in your Thing.

### Zigbee2MQTT

Publishes to `zigbee2mqtt/[device]/availability`.
Map this in your Thing.

## Summary

The universal pattern:
1. Device publishes to `home/device/[name]/status` = `online`/`offline` (retained)
2. openHAB MQTT Thing subscribes to that topic
3. Switch item reflects online/offline state
4. Group membership allows statistics and UI display

This works for ANY device that can publish MQTT messages!

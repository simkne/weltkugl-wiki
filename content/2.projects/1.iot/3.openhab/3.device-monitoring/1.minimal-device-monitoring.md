Let's get ONE device working first before adding more complexity.

## Step 1: Verify MQTT on openHABian

### 1.1 Check if Mosquitto is running

```bash
# SSH into your Pi
ssh openhabian@your-pi-ip

# Check if Mosquitto is running
sudo systemctl status mosquitto

# If not running:
sudo systemctl start mosquitto
sudo systemctl enable mosquitto
```

### 1.2 Test MQTT manually

On your Pi, open two terminals:

**Terminal 1 — Subscribe:**
```bash
mosquitto_sub -h localhost -t "esphome/+/status" -v
```

**Terminal 2 — Publish test:**
```bash
mosquitto_pub -h localhost -t "esphome/test/status" -m "online" -r
mosquitto_pub -h localhost -t "esphome/test/status" -m "offline" -r
```

You should see the messages in Terminal 1.

### 1.3 Check MQTT credentials

```bash
# Check if you have authentication configured
cat /etc/mosquitto/conf.d/default.conf

# If using authentication, test with credentials:
mosquitto_sub -h localhost -u openhabian -P yourpassword -t "#" -v
```

## Step 2: Verify ESP32 is publishing

### 2.1 Check secrets.yaml

Make sure these are set correctly:

```yaml
# /Users/simon/Documents/PlatformIO/Projects/esp32-s3-esphome/secrets.yaml
mqtt_broker: 192.168.1.XXX # Your Pi's actual IP, NOT localhost
mqtt_user: openhabian # Or whatever user you use
mqtt_password: yourpassword
```

::caution
Using `localhost` or `127.0.0.1` in secrets.yaml won't work from the ESP32 — that resolves to the ESP32 itself. Use the Pi's actual IP address.
::

### 2.2 Flash and monitor

```bash
cd /Users/simon/Documents/PlatformIO/Projects/esp32-s3-esphome
esphome run esp32-s3-zero-one.yaml
```

Watch the logs. You should see:
```
[monitoring]: Published online status - IP: 192.168.1.XXX
```

### 2.3 Check if ESP32 is publishing

On your Pi:
```bash
# Subscribe to all ESPHome topics
mosquitto_sub -h localhost -t "esphome/esp32-s3-zero-one/#" -v
```

You should see:
```
esphome/esp32-s3-zero-one/status online
esphome/esp32-s3-zero-one/ip 192.168.1.XXX
esphome/esp32-s3-zero-one/heartbeat 23.5
esphome/esp32-s3-zero-one/rssi -45
```

**If you don't see these messages, the ESP32 isn't connecting to MQTT.**

## Step 3: Create ONE Item in openHAB

Don't copy all the files yet — let's create just ONE item to test.

### 3.1 Create the items file

On your Pi:
```bash
sudo nano /etc/openhab/items/test_monitoring.items
```

Add ONLY this:
```java
// Test monitoring - just one device
Switch Test_Online "ESP32 Test Online"
```

### 3.2 Create the MQTT Thing

In MainUI:
1. Settings → Things → Add → MQTT Thing
2. If you don't have a Broker yet, create one first:
   - Add → MQTT Broker
   - Thing ID: `broker`
   - Host: `localhost` (or `192.168.1.XXX` if openHAB is not on the same machine)
   - Port: `1883`
   - Username/Password: your MQTT credentials

3. Now create the Thing:
   - Bridge: Select your broker
   - Thing ID: `esp32test`
   - Label: "ESP32 Test Device"

4. Add a Channel:
   - Channel ID: `online`
   - Type: `Switch`
   - State Topic: `esphome/esp32-s3-zero-one/status`
   - ON: `online`
   - OFF: `offline`

5. Link to Item:
   - Click the channel → Add Link
   - Item: `Test_Online`

### 3.3 Test it

In MainUI:
1. Go to Settings → Items → Test_Online
2. You should see the state change when the ESP32 connects/disconnects

To test:
- Unplug ESP32 → wait 60-90s → should show OFF
- Plug back in → should show ON within 10s

## Step 4: Add to a Page

Once the item works, add it to a page:

1. Settings → Pages → Your Overview Page
2. Add Widget → Custom Widget
3. Add this simple widget YAML:

```yaml
component: f7-card
config:
  title: Device Test
slots:
  default:
    - component: f7-row
      config:
        style:
          padding: 20px
          backgroundColor: "=(items.Test_Online.state === 'ON') ? '#e8f5e9' : '#ffebee'"
      slots:
        default:
          - component: Label
            config:
              text: "=(items.Test_Online.state === 'ON') ? 'Online' : 'Offline'"
              style:
                fontSize: 24px
                fontWeight: bold
                color: "=(items.Test_Online.state === 'ON') ? 'green' : 'red'"
```

## Debugging Checklist

### ESP32 not connecting to MQTT?

Check serial logs:
```bash
esphome logs esp32-s3-zero-one.yaml
```

Look for:
- `Connecting to MQTT...`
- `MQTT connected`
- Any errors

Common issues:
1. **Wrong broker IP** — must be Pi's IP, not localhost
2. **Wrong credentials** — check username/password
3. **Firewall** — check if port 1883 is open on Pi
4. **MQTT not running** — `sudo systemctl status mosquitto`

### MQTT working but openHAB not updating?

Check:
```bash
# On Pi, verify the topic
mosquitto_sub -h localhost -t "esphome/esp32-s3-zero-one/status" -v

# If you see messages here but not in openHAB:
# - Check Thing configuration
# - Check channel topic spelling
# - Check item link
```

### Still not working?

Test with MQTT Explorer (desktop app):
1. Connect to your Pi's MQTT broker
2. Subscribe to `esphome/#`
3. Check if messages appear when ESP32 connects

## Working Configuration Summary

Once working, you should have:

**ESPHome YAML:** MQTT publishing to `esphome/esp32-s3-zero-one/status`

**MQTT Broker:** Running on Pi, accessible from ESP32

**openHAB Thing:**
- Bridge: MQTT Broker
- Thing: MQTT Topic
- Channel: Switch linked to `esphome/esp32-s3-zero-one/status`

**openHAB Item:** `Test_Online` linked to the channel

**Page Widget:** Shows green/red based on item state

Only when this works, proceed to add the full monitoring system!

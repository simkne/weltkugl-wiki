You likely already have ESPHome devices running. Here's how to add monitoring without breaking anything.

## Step 1: Identify Your Current Setup

### Check Your Current ESPHome Items

```bash
# List existing ESPHome-related items
grep -r "esphome" /etc/openhab/items/

# Or check in MainUI: Settings → Items → Search "esphome"
```

### Common Patterns

You probably have items like:
- `LivingRoom_Temperature`
- `LivingRoom_Humidity`
- `ESPHome_LivingRoom_Status` (maybe)

## Step 2: Add Monitoring Without Disruption

### Option A: Add Status to Existing Device (Recommended)

Add new items alongside existing ones:

```java
// File: items/livingroom_esphome.items

// YOUR EXISTING ITEMS (keep these!)
Number LivingRoom_Temperature "Living Room Temp [%.1f °C]" <temperature>
    { channel="esphome:device:livingroom:temperature" }
Number LivingRoom_Humidity "Living Room Humidity [%.0f %%]" <humidity>
    { channel="esphome:device:livingroom:humidity" }

// NEW: Add these for monitoring
Switch LivingRoom_Online "Living Room ESP" <presence> (gESPHomeDevices, gOnlineDevices)
    { channel="esphome:device:livingroom:online" }
DateTime LivingRoom_LastSeen "Last Seen [%1$ta %1$tR]" <time>
Number LivingRoom_RSSI "WiFi Signal [%d dBm]" <network>
    { channel="esphome:device:livingroom:wifi_signal" }
String LivingRoom_IPAddress "IP [%s]" <network>

// Alert tracking
Switch DeviceAlert_LivingRoom "Living Room Alert" <siren>
```

### Option B: Use Existing Status Item

If you already have a status item, just rename it to match the pattern:

```java
// Old name (in your existing items file)
Switch ESP32_LivingRoom_Status "Living Room [%s]" <presence>

// Change to:
Switch LivingRoom_Online "Living Room ESP" <presence> (gESPHomeDevices, gOnlineDevices)
    { channel="esphome:device:livingroom:online" }
```

Then update any existing rules/widgets that reference the old name.

## Step 3: Update ESPHome Firmware (if using MQTT)

If your devices don't have MQTT with LWT, add this to their YAML:

```yaml
# Add to your existing device YAML

mqtt:
  broker: !secret mqtt_broker_ip

  # Last Will Testament - critical for offline detection
  will_message:
    topic: esphome/livingroom/status
    payload: offline
    retain: true

  birth_message:
    topic: esphome/livingroom/status
    payload: online
    retain: true

# Publish on boot
esphome:
  on_boot:
    priority: -100
    then:
      - mqtt.publish:
          topic: esphome/livingroom/status
          payload: online
          retain: true
```

Flash and restart the device.

## Step 4: Create MQTT Thing (if not using Native API)

In MainUI:

1. **Settings → Things → Add → MQTT Thing**
2. **Bridge:** Select your MQTT broker
3. **Thing ID:** `livingroom`
4. **Label:** "Living Room ESP"

### Add Channels

| Channel ID | Type | State Topic | Transformation |
|------------|------|-------------|----------------|
| `online` | Switch | `esphome/livingroom/status` | MAP:online.map |
| `rssi` | Number | `esphome/livingroom/rssi` | — |
| `ip` | String | `esphome/livingroom/ip` | — |

Create `transform/online.map`:
```
online=ON
offline=OFF
NULL=unknown
-=unknown
```

### Link to Items

| Channel | Item |
|---------|------|
| `online` | `LivingRoom_Online` |
| `rssi` | `LivingRoom_RSSI` |
| `ip` | `LivingRoom_IPAddress` |

## Step 5: Update Your Existing Widgets

If you have existing widgets, add visual indicators:

### Add Status Indicator to Existing Sensor Widget

```yaml
# Add to your existing sensor widget

- component: f7-row
  config:
    style:
      alignItems: center
      gap: 8px
  slots:
    default:
      - component: f7-icon
        config:
          f7: "=(items.LivingRoom_Online.state === 'ON') ? 'checkmark_circle_fill' : 'exclamationmark_triangle_fill'"
          color: "=(items.LivingRoom_Online.state === 'ON') ? 'green' : 'red'"
          size: 18
      - component: Label
        config:
          text: =items.LivingRoom_Temperature.state + '°C'
          style:
            fontSize: 24px
            fontWeight: bold
```

### Or Use the Compact Indicator in Headers

Add `device_compact_indicator` widget to your page header to show overall status.

## Step 6: Test Without Breaking Things

### Safe Testing Checklist

1. **Keep existing items unchanged** — only add new ones
2. **Test one device first**
3. **Verify openHAB shows correct status**:
   - Device online: `LivingRoom_Online` = ON, green icon
   - Unplug device: `LivingRoom_Online` = OFF after 60s, red alert
   - Plug back: `LivingRoom_Online` = ON, alert clears
4. **Check existing rules still work**

### Rollback if Needed

```bash
# If something breaks, just remove the new items:
sudo rm /etc/openhab/items/device_monitoring.items
sudo rm /etc/openhab/items/esphome_devices.items
sudo rm /etc/openhab/rules/device_monitoring.rules

# Restart openHAB
sudo systemctl restart openhab
```

## Step 7: Migrate Gradually

### Phase 1: Add Monitoring (Day 1)
- Add status items for all devices
- Add widgets
- Observe for a few days

### Phase 2: Add Alerts (Day 3+)
- Enable `DeviceMonitor_AlertOnOffline`
- Test alerts with one device
- Adjust timeout if needed

### Phase 3: Notifications (Later)
- Install Pushover binding
- Uncomment notification code in rules
- Test with your phone

## Common Migration Scenarios

### Scenario 1: Already Using ESPHome Binding

You have:
```java
// Existing
Number LivingRoom_Temp { channel="esphome:device:livingroom:temperature" }
```

Add:
```java
// New
Switch LivingRoom_Online { channel="esphome:device:livingroom:online" }
```

The ESPHome binding already provides the `online` channel!

### Scenario 2: Using MQTT for Sensors

You have:
```java
// Existing
Number LivingRoom_Temp { channel="mqtt:topic:livingroom:temperature" }
```

Add to your Thing:
```java
Type switch : online [
    stateTopic="esphome/livingroom/status",
    on="online",
    off="offline"
]
```

Then add item:
```java
Switch LivingRoom_Online { channel="mqtt:topic:livingroom:online" }
```

### Scenario 3: Mixed Setup (Some Native API, Some MQTT)

Use both:

```java
// Native API devices
Switch LivingRoom_Online { channel="esphome:device:livingroom:online" }

// MQTT devices
Switch Bedroom_Online { channel="mqtt:topic:bedroom:online" }

// Both in same group
// Rules work with both automatically
```

## Verification Script

Run this in openHAB console to verify setup:

```bash
openhab-cli console

# Check all online items
openhab> items list | grep _Online

# Check device stats
openhab> items get DeviceStats_Total
openhab> items get DeviceStats_Online
openhab> items get DeviceStats_Offline

# Test one device
openhab> items get LivingRoom_Online

# Simulate offline (for testing)
openhab> openhab-send LivingRoom_Online OFF

# Check if alert appears
openhab> items get DeviceAlert_LivingRoom

# Restore
openhab> openhab-send LivingRoom_Online ON
```

## Troubleshooting

| Issue | Solution |
|-------|----------|
| Existing items have different naming | Use `Switch MyWeirdName as LivingRoom_Online` or update widget references |
| Devices use different topic structure | Update channel configs to match your topics |
| Don't want to reflash all devices now | Start with Native API devices (no reflashing needed) |
| Worried about breaking existing setup | Test on one device first, keep backups |

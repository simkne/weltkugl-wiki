## What is openHAB?

**openHAB** (Open Home Automation Bus) is a mature, vendor-neutral automation platform that connects virtually any smart device — lights, sensors, plugs, locks, thermostats, cameras, custom microcontrollers — into a single, coherent system.

Unlike cloud-locked ecosystems (proprietary hubs that stop working when the manufacturer changes pricing or goes out of business), openHAB runs **entirely on your own hardware**. Your data stays local. Your automations keep running even if your internet connection drops. And you are never forced into a subscription.

In our setup, openHAB lives on a **Raspberry Pi 4** running **OpenHABian** — a ready-to-use Linux image that bundles openHAB, an MQTT broker (Mosquitto), and a suite of maintenance tools. Custom **ESP32-S3** and **ESP32-C6** sensor nodes talk to the Pi over MQTT, while commercial devices (Shelly, Tasmota-flashed gear, and others) integrate through their native protocols or MQTT as well.

## Why openHAB?

| Advantage | What it means in practice |
|-----------|---------------------------|
| **Open source** | Full source code available, no licensing fees, community-driven development. If a binding breaks, the community fixes it — or you can. |
| **Vendor-agnostic** | Mix and match brands freely. Philips Hue bulbs, Shelly relays, Zigbee sensors, Z-Wave locks, DIY ESP32 nodes, and cloud APIs can all coexist in one system. |
| **Runs locally** | No dependency on external cloud services for core logic. Automations execute on the Pi. Latency is minimal. Privacy is maximal. |
| **Highly flexible** | Configure through the modern Main UI, write rules in multiple languages (DSL, JavaScript, Blockly, Python), or edit text files directly. There is no "one true way." |
| **Rich ecosystem** | Hundreds of bindings for protocols and services: MQTT, Zigbee, Z-Wave, KNX, Modbus, HTTP, Alexa, Google Home, InfluxDB, and many more. |
| **Mature & stable** | Over a decade of active development. Strong backward-compatibility policy. Extensive documentation. |

For a hobbyist or side-project setup, these traits matter enormously. You can let the project sit for weeks, come back, and everything still works. You can add a new device from a different brand without replacing your entire stack. And when something breaks, you have full visibility into *why*.

## Core concepts in 60 seconds

openHAB's architecture revolves around a few key abstractions. Understanding them makes everything else click.

### Things
A **Thing** represents a physical device or service endpoint — an MQTT broker, a Zigbee coordinator, a Shelly plug, or an ESP32 sensor node. Things expose **channels** (individual data points like temperature, switch state, or online status).

### Items
An **Item** is a named, typed variable in openHAB's internal state machine. Items receive data from Thing channels and can be read by rules, displayed in the UI, or persisted to databases for history and charting.

### Bindings
A **binding** is an adapter that lets openHAB speak a specific protocol or API — MQTT, Zigbee, HTTP, ESPHome, etc. Install the binding, create a Thing, link channels to Items, and the device is integrated.

### Rules
**Rules** are automations: *when* something happens, *then* do something. Triggers can be Item state changes, time schedules, system events, or even external HTTP calls. Rules can be written in the legacy DSL, JavaScript, Blockly (visual), or Python.

### Sitemaps & Main UI
The **Main UI** (new in openHAB 3+) is a modern, responsive web interface for controlling your home. **Sitemaps** are the older, XML-based layout format still supported for compatibility. For new setups, Main UI is the way to go.

### Persistence
**Persistence** stores historical Item states so you can chart trends, compute averages, or check "when was this last updated?" openHAB ships with `rrd4j` (lightweight, fixed-size), and optional addons like InfluxDB are available for heavier analytics.

## Quick start for newcomers

If you are starting from zero and want a setup like ours:

1. **Get the hardware** — A Raspberry Pi 4 (4 GB minimum, 8 GB recommended), a quality power supply, and a microSD card (or better, an SSD).
2. **Flash OpenHABian** — Download from [openhab.org](https://www.openhab.org/docs/installation/openhabian.html), flash to SD/SSD, boot the Pi.
3. **Complete first-boot setup** — SSH in, change default passwords, run `sudo openhabian-config` to update.
4. **Install bindings** — Start with the **MQTT binding** and any binding for your existing devices (Zigbee, Z-Wave, etc.).
5. **Create your first Thing and Item** — Connect a simple device (a Shelly plug or an ESP32 sensor) and verify state changes in Main UI.
6. **Write your first rule** — "When motion sensor turns ON, turn on hallway light for 5 minutes."
7. **Iterate** — Add devices, refine rules, build dashboards. There is no finish line.

For detailed step-by-steps, the [official openHAB docs](https://www.openhab.org/docs/) are excellent. The articles in this section focus on the specific patterns, pitfalls, and maintenance rhythms we've discovered while running the system day-to-day.
